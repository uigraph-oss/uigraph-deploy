# UIGraph on EKS

Run the full UIGraph stack — API, GraphQL, gateway, UI, MCP — on your own AWS account. Bring your
own EKS cluster or let Terraform build one. No standing AWS credentials, anywhere.

```bash
cd terraform/platform
cp terraform.tfvars.example terraform.tfvars   # your cluster, your domain
terraform init && terraform apply
```

## What you get

- **Your infrastructure, your account.** Deploy into an EKS cluster you already run, or have
  Terraform build one from scratch. Your VPC, your data, your IAM boundary.
- **No static AWS keys.** Every service — object storage, cost visibility — authenticates through
  its pod's IAM role. Nothing generated to leak, nothing to rotate.
- **Public or fully internal, your call.** One variable switches between an internet-facing ALB
  and a VPN-only deployment.
- **Scales by default.** API, GraphQL, gateway, and UI each run as independent, autoscaling
  Deployments behind a shared ALB.
- **Cost visibility across any number of AWS accounts.** Connect the account you deploy into, or
  any other account your org owns — no code changes, just an IAM role per account.
- **AI assistants included.** MCP server ships as a first-class component, reachable over its own
  domain.

## Architecture

```
terraform/
├── cluster/    # optional — skip if you already run EKS
└── platform/   # RDS, ElastiCache, S3, IAM, and the app itself
```

Two independent Terraform states, each fully apply/destroy-able on its own. Already run EKS? You
only ever touch `platform/`. Starting from nothing? `cluster/` builds a VPC and cluster first,
~15 minutes, then `platform/` runs the same way against it.

## Configuration

| | |
|---|---|
| Bring your own EKS, or build one | run `cluster/`, or skip it |
| Public or internal-only | `exposure_mode` |
| HTTPS — automated or bring your own cert | `route53_zone_id` / `acm_certificate_arn` |
| Cost Explorer for this account | `enable_cost_explorer_access` |
| Image tags, resources, replicas, anything else | `helm_values_override` |

Full reference: `variables.tf` in each folder. Day-2 operations, troubleshooting, and connecting
additional AWS accounts for billing: [`OPERATIONS.md`](OPERATIONS.md).

## Security posture

- IRSA only — no IAM users or access keys created for the app to run.
- Least privilege by construction: the app's role reaches only its own S3 bucket; cost visibility
  is a separate, revocable role, not permissions bolted onto the app's core identity.
- Bring your own secrets management — Terraform-generated by default, or External Secrets
  Operator + AWS Secrets Manager for a hardened setup.

## Cost

~$0.30–0.40/hr at default sizing. Multi-AZ, larger instances, and Multi-AZ RDS raise that;
`single_nat_gateway` and `t4g.micro`/`t3.medium` defaults keep it low for dev and test.

## Tear down

```bash
cd terraform/platform && terraform destroy
cd ../cluster && terraform destroy   # only if you ran it
```
